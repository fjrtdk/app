# Milestone v1.0: Firebase Auth Migration

**Status:** ✅ SHIPPED 2026-05-11
**Phases:** 1-5
**Total Plans:** 8 (1 deferred)

## Overview

Replace Emergent Google OAuth with Firebase Google sign-in across the full stack. Backend gets Firebase Admin SDK for ID token verification, frontend gets Firebase JS SDK for sign-in popup. Session cookie format stays the same so all guarded endpoints keep working. All Emergent dependencies, badge, PostHog, and visual-edits stripped.

### Phase 2: Backend Firebase Integration

**Goal**: Backend accepts Firebase ID tokens and issues session cookies
**Depends on**: Phase 1
**Plans**: 2 plans

Plans:
- [x] 02-01: Add firebase-admin, init Firebase in server.py, create verify_firebase_token helper

**Details:**
- Firebase Admin SDK initialized from env vars via Certificate(dict)

- Graceful fallback when Firebase env vars missing

## Milestone Summary

**Key Decisions:**
- Firebase ID token → custom session cookie (reuses existing guarded endpoints)
- Firebase Admin SDK on backend, Firebase JS SDK on frontend
- Popup over redirect for sign-in
- Credentials via env vars only (Certificate(dict), no file path)
- Start fresh — no user migration from Emergent sessions

**Issues Resolved:**
- All Emergent dependencies removed (auth, badge, PostHog, visual-edits)
- Auth flow complete: signInWithPopup → ID token → backend verify → session cookie
- Session cookie format preserved — zero changes to guarded endpoints

**Issues Deferred:**
- Plan 05-02: Manual E2E auth flow verification (needs live MongoDB + NIM)
- Pre-existing craco build failure (ajv-keywords module resolution — unrelated to this work)
- Yarn lockfile out of sync (firebase installed via npm --legacy-peer-deps)

**Technical Debt Incurred:**
- Yarn lockfile needs regeneration
- Firebase package added via npm instead of yarn
